# Fixed scalar arrays: gated reference execution

This phase implements and qualifies reference execution for fixed scalar arrays in RFC0016 Unit 2C. The production verifier still rejects every array carrier and opcode. Source grammar and selectors remain closed for fixed arrays. Native execution was pending at this reference checkpoint; the later [private native ledger](fixed-array-unit2d-validation.md) records its separate qualification. These results do not activate public array support.

## Authoritative boundary and execution

The cfg(test) bridge is confined to `verified.rs`. It uses the same preparation and complete validation continuation as production, constructs the existing sealed witness locally, calls the real reference consumer synchronously, and returns only copied outcomes, traces and storage observations. A shared entry helper preserves entry-result and parameter rejection before execution-plan allocation. No raw body, declarations, witness, plan, callback, global bypass or environment toggle escapes. Production carrier/opcode rejection remains mandatory and unchanged.

The reference consumer implements ConstructArray, ReadIndex, WriteIndex and ArrayLength. Array construction validates every immutable scalar snapshot before writing any payload, using two bounded passes without a per-operation element vector. Whole values move scalar-wise through local and temporary initialization, both replacement states, staged arguments, incoming owned parameters and returned call results. Incoming owned transfer has its own implemented array branch. Empty arrays initialize their complete positive sentinel, including all four bytes of empty i32 storage; unit arrays write canonical zero bytes for all elements.

Each operation pays fuel before runtime identity, permission and scalar/type validation. Indexed access then checks signed i32 bounds before conversion, multiplication, offset addition or memory access. Failed bounds produce exactly `E0606`, stage `oir-owned-run`, message `array index out of bounds`, using the validated primary access span and normal SourceMap filtering. ArrayLength performs a full readable-base check even at length zero. Full element type and length are compared through the shared aggregate facade; arrays are never converted to nominal record identities. Existing frame/owner generations and loan-instance keys provide provenance without a new runtime type tag.

ConstructArray costs `1 + max(1, N)`; ReadIndex, WriteIndex and ArrayLength each cost one. Whole-owner operations use the existing aggregate-width formulas. Record scalar encode/decode was factored into shared helpers; compatibility is demonstrated by fresh existing reference/plan tests and ordinary profiles rather than claimed byte identity.

## Resources and bounded observations

Production X, Dref, Dnative, Mplan and all admission limits remain unchanged. There is no new production retained table, vector or element scratch. Reference frame layout remains 272 bytes. Exact and one-under fuel, frame, slot, cell and requested-byte controls include empty i32 and bool arrays, nonempty unit arrays, and maximum length 1024. Every actual plan/frame reservation index is exercised independently of observation allocation.

The cfg(test) observer retains at most 16,384 events, 64 storage rows and 262,144 copied payload bytes. Each payload is at most 4096 bytes. Checked counts and byte arithmetic precede fallible reservations and copies. Actual measured row sizes are Event 72 and StorageSnapshot 80 bytes; the originally proposed conservative bounds of 80 and 128 bytes remain unchanged. Their requested retained payload ceilings are 1,310,720 event bytes, 8192 row bytes and 262,144 payload bytes, plus fixed headers/state. These are requested-payload bounds, not total RSS claims.

Truncation stops further collection, poisoning and runtime-fault application while preserving the language result. All owner states are observed on terminal failure, and before a returning frame is removed, so earlier helper effects and an absent final store are verified from bytes as well as events. Construction/Transfer snapshots carry destination identity/state from before the write and bytes from afterward; Incoming carries intended installed identity; indexed-write/return/failure snapshots carry current state. Poison tests initialize complete destination extents before the real successful write path and compare adjacent guard bytes. Poison mode is not used to establish no-write-on-denial behavior.

Ten closed one-shot runtime corruptions exercise constructor snapshot atomicity, stale owner/loan keys, suspended permissions, root equality, full reference type and incoming alias/type checks. They modify only explicitly named runtime scalar/handle/loan rows and then run the same consumer checks. A selector is consumed at the first matching successfully charged statement or Invoke hook, even if inapplicable; activation, merge, branch, goto and return charges have no such hook. Applied flags prevent vacuous evidence.

Three separate closed observer selectors simulate the first Event, StorageHeader or Payload reservation failure through the same truncation branches used by real reservation errors. They have no arbitrary counter or callback, do not affect production reservation hooks, publish no partial snapshot row and preserve the runtime outcome. Exact observer caps and checked payload-ledger overflow are tested separately.

## Retained failed attempts and forward limits

Early focused tests found two expectation mistakes: an inclusive relay-run total of 609 instead of independently derived 591, and an expected Event size of 80 instead of measured 72. The relay formula `2N + 58 + 25w` gives sufficient fuel 83/112 at N = 0/2, hence `3 × (84 + 113) = 591` budgets. The conservative 80-byte event cap was preserved. No semantic expectation or production behavior changed for either correction.

Initial compile attempts contained a renamed test-event variable and a missing test-only re-export. The first cfg(test) privacy run exposed missing existing include_str inputs in the temporary-copy harness; copying the existing RFC and fixture trees fixed it. Final Clippy required three mechanical test idiom corrections without changing expectations. Their failed logs and earlier executable are retained separately from qualified results.

Native array lowering, bounds-dominant addresses, continuation/phi handling, diagnostic coordinate batching, LLVM/ELF execution and native physical-sentinel/resource gates remain Unit 2D.
