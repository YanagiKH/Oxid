# Fixed scalar arrays: reference execution checkpoint

This checkpoint adds reference execution for fixed scalar arrays as part of RFC0016 Unit 2. The authoritative production verifier still rejects every array carrier and opcode. Source grammar, all source selectors and the native consumer remain closed for arrays. This is phase progress, not completed Unit 2 qualification or public array support.

The test-only bridge lives inside verified.rs. It invokes shared preparation and validation, constructs the existing sealed witness locally, calls the actual reference consumer synchronously and returns only bounded copied outcomes/events/storage. A shared runtime entry helper preserves entry-before-plan rejection. No raw body, declarations, witness, plan, callback, environment switch or global admission toggle escapes.

Reference changes implement E0606 / oir-owned-run / array index out of bounds, scalar snapshot construction, scalar-wise whole transfers and separate incoming-owner copying, signed bounds before checked address arithmetic, full aggregate identity and permission rechecks, and full positive sentinel initialization. Record scalar encoding/decoding is factored into shared helpers. Existing record behavior, costs and diagnostic strings are intended to remain compatible; the affected reference/plan regression results are recorded separately from source-byte identity. ConstructArray uses 1 + max(1, N); indexed read/write and length each use 1. All production storage/resource formulas remain unchanged.

A cfg(test) observer has a 16,384-event cap, 64-snapshot cap and 262,144 cumulative payload-byte cap. Its new reservations are fallible and outside production reservation hooks. Truncation stops collection/poisoning and does not change the language result. Snapshot identity/state for Construction and Transfer refers to the destination before the write; bytes refer to the completed write. Incoming records intended installed identity; indexed-write/return/failure snapshots record current state. All-state terminal snapshots preserve evidence of surviving helper effects and failed final writes.

Accepted API v2 anticipated Event 80 and Snapshot ≤ 128, retaining conservative requested-payload ceilings of 1,310,720 and 8,192 bytes respectively. Actual compiled measurements are Event 72, Snapshot 80 and unchanged Frame 272. The original expectation and failed measurement attempt are retained; the conservative caps are not reduced. This is a measurement clarification, not widened admission.

Provenance extension v2 adds 10 closed one-shot runtime fault variants at exact successfully charged origins. Faults mutate only the named scalar snapshot/handle/loan row, then the same real consumer code checks it. The immutable witness/program/types/plan are untouched. fault_applied distinguishes exercised from inapplicable probes. These are explicitly adversarial invariant tests, separate from ordinary semantic traces and destination poison tests.
