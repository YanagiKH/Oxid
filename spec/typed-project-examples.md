# Typed-project example acceptance fixtures

This corpus is a frozen, hand-authored acceptance oracle for the typed-preview CLI. It is test infrastructure only; it does not add a public doctest or compile-fail command. The compiled test harness owns the fixed registry—do not add a registry file or derive required cases from mutable fixture contents.

## Corpus and fixed expectations

The corpus root is `tests/fixtures/typed_project_examples/`. C01–C08 and D01–D04 are independent projects; D01–D04 documents live at `docs/D01.md` through `docs/D04.md`. Manifests and source bytes are normative. Text is UTF-8 without BOM, LF, and exactly one final LF; C08 `main.ox` is exactly one byte `FF` with no newline. Do not format, normalize, or regenerate fixtures from compiler output.

The fixed executable inventory is C01 check-pass; C02, C03, C07, C08 compile-fail; C06 check-pass; D01 doc-check; D02 doc-run. C04 and C05 are isolated reject-selftests, D04 is an isolated document-mismatch reject-selftest, and D03 is an inert-policy selftest—not an executable example. The complete inventory has all twelve IDs exactly once with these categories.

Hand-authored CLI outcomes: C01 succeeds with one function; C02 has one E0100/parse diagnostic at `main.ox` bytes [28,29); C03 has one E0300/type diagnostic at `main.ox` [26,30); C06 succeeds with two functions; C07 has one E0300/type diagnostic at `helper/lib.ox` [31,35); C08 has one E0003/source diagnostic with `primary: null`. D01 checks successfully and is never run. D02 checks successfully, then runs once and emits exactly `7\n` (bytes `37 0A`) with exit 0. D03 has no compiler result because its ordinary `oxid` fence is inert. C04 must be rejected specifically as `diagnostic-code-mismatch(expected=E0100, actual=E0300)`; C05 specifically as `expected-compile-failure-but-check-succeeded`; D04 specifically as `doc-fixture-byte-mismatch`, first difference document offset 41 (`38`) versus source offset 26 (`37`). All other expected diagnostics have empty `secondary` and `notes`. Diagnostic message text is checked as a string, not frozen wording.

Every document mapping is a fixed byte slice, not fence discovery: D01–D03 use document bytes [15,46), exactly equal to their `main.ox` bytes [0,31); each document is 50 bytes. D04 has the same source and fixed slice but intentionally differs at the stated byte. Verify the complete document, heading, fence, range, source length, and bytes. Never trim, search, auto-correct, or execute arbitrary Markdown fences.

## Global preflight and isolation

Before any compiler process starts, validate the entire selected inventory: required IDs and categories, uniqueness, valid modes, nonempty executable selection, all declared files and exact bytes, and all fixed document mappings. Missing/extra required cases, duplicate IDs, missing or unexpected files, invalid modes, an empty normal list, or zero executable selections are configuration failures with zero launches. D04 must remain isolated from normal cases. Test a valid D01 followed by malformed D04 to prove validation is global and completes before launch. D03's zero executable registrations and absent compiler results are success only for its separately named inert-policy test; they do not waive normal required-inventory checks.

Use disposable project copies so tests cannot alter tracked fixtures. All compiler invocations—real adapter and spy alike—must pass through one launcher seam. Execute argv directly, never through a shell, and resolve the tested executable using `env!("CARGO_BIN_EXE_oxid")`. The working directory is the copied case root. CHECK argv is exactly `check --manifest-path=oxid.toml --message-format=json`; RUN argv is exactly `run --manifest-path=oxid.toml --entry-mode=result`. Do not invoke build, test, doc, native, or provider commands. D01's spy must observe exactly CHECK and no RUN. D02 must observe exactly CHECK then RUN after valid CHECK success; invalid or failed CHECK forbids RUN. D03 and D04 launch nothing. A spy proves only harness launch behavior, not compiler-internal execution; distinguish that observation from static source evidence.

For Linux path checks, compare exact relative component paths `main.ox` and `helper/lib.ox`. Permit only the documented single `./` prefix or a proven working-directory prefix removal; reject traversal, external roots, basename/suffix matching, and unknown normalization. Do not canonicalize away diagnostic identity or apply path normalization to source bytes. C08 has no primary path; do not infer one from its message. A span's `file_id` is a nonnegative integer consistent for the same source, not a frozen traversal number.

## JSONL and process protocol

Parse stdout as newline-terminated UTF-8 JSON Lines, one complete object per nonblank line. Reject blank lines, invalid UTF-8, unterminated lines, trailing garbage, multiple values on a line, malformed JSON, wrong types, missing/extra protocol fields, and extra records. Use a strict JSON reader and typed structural checks; this scope does not promise duplicate object-member rejection before value construction. Duplicate diagnostic records and duplicate summaries must still be counted and rejected as appropriate.

A diagnostic has exactly the protocol fields `schema_version`, `edition`, `kind`, `severity`, `code`, `stage`, `message`, `primary`, `secondary`, and `notes`: version 1, edition `typed-preview`, kind `diagnostic`, severity `error`; strings for code/stage/message; primary null or a complete span object; secondary and notes arrays (empty for this corpus). A non-null span contains nonnegative integer `file_id`, `start`, `end`, `line`, `column`, `end_line`, and `end_column`, plus a path matching the exact case-relative source. Validate the frozen code, stage, source slice, half-open byte offsets, and 1-based line/column positions.

Exactly one summary is required, and it must be last: fields `schema_version=1`, `edition="typed-preview"`, `kind="check-summary"`, boolean `success`, nonnegative integer `errors`, and `functions` (a nonnegative integer on success, null on failure). `success` agrees with `errors == 0`, and `errors` equals the diagnostic count. Success has no diagnostics and functions is exactly 1, except C06's 2. Each failure has exactly its one frozen diagnostic, errors 1, and functions null. Do not freeze diagnostic wording or upstream ordering; if comparing diagnostic lists, compare full expected projections as an unordered multiset preserving multiplicity.

Expected CHECK success exits 0 with empty stderr. Expected compile failures exit 1 with exactly one diagnostic and empty stderr. Exit 2, signals, other exit codes, launch/read/wait failures, timeout, output-limit violation, or stderr contamination are infrastructure/protocol failures, never expected compile failures. D02 RUN requires exit 0, stdout exactly bytes `37 0A`, and empty stderr. Do not fabricate a process result where no invocation occurred.

Use a documented per-child timeout of 30 seconds. Drain stdout and stderr concurrently, check read and wait errors, and kill and reap timed-out children; never wait on a full pipe before enforcing timeout. Cap harness-captured output at 1 MiB per stream and classify overflow as infrastructure failure, not a compiler limit. Keep spawn, read, wait, timeout, signal, and output-limit failures distinguishable and ensure no child remains running after error.
