# Mandatory Unit4 activation integration

This integration owns orchestration and evidence transport only. It does not
change the public semantic contracts, portable parser, hosted capability
controller, or existing CI gate responsibilities. Current compiler and observer
identities are explicitly refreshed for the reviewed formatter and prior
fixed-array groundwork; the lifecycle observer overlay and historical
source/corpus authorities stay unchanged.

## Trust and command interfaces

`gate.py host --repo REPO --output FRESH --expected-head SHA --event-sha SHA
--host HOST [--historical-repo REPO --toolchain ROOT --cargo-cache CACHE]` is the
mandatory actual-host route. All admitted component files, membership, source185,
Git head/full tree, contract transport and amendments are checked before importing
component code, writing materialized inputs, or executing a compiler. Inputs are
rechecked before every stage and before completion. HOST is an expectation checked
against platform measurements, never a simulated host selector. The PR workflow
checks out the event PR head explicitly and records `github.sha` separately as
`event_sha` (which can be GitHub's synthetic merge SHA). Both values are preserved;
the event SHA is never mislabeled as the compiler checkout head.

Linux creates ordinary and lifecycle debug/release binaries, stages the exact
LLVM19.1.7 runtime, executes all five frozen public sections, preserves the root
main run's exit2 and twelve capability gaps, and invokes the independently
reviewed existing-UID controller to close exactly those keys with raw evidence.
The controller is required to exercise its real root branch in CI. Local nonroot
controls cannot replace it. The same job then prepares the exact historical
`d9e6b9bf172abd5e15da7212c9e6224e29ccc768` Git authority, proves current compiler
identity independently, builds all four parser binaries, checks twelve passivity
pairs and compares638 observations under the exact effective amendment.

Each non-Linux host builds ordinary and lifecycle profiles and executes all five
sections. Public/original/lifecycle have positive scope; predecessor/guard zero
scope is admitted only from complete frozen exclusion rosters. The reviewed
no-native trap must actually build, execute, log and return121 on each host.

`join.py --repo REPO --artifacts DIR --output FRESH --expected-head SHA
--event-sha SHA` is an always-running mandatory final job. It requires exactly
one complete evidence capsule for each of the four measured hosts, consistent
head/tree/source/contracts/components, the exact local roster plans and two
profiles per applicable section. Counts are derived from the frozen rosters and
raw actual rows. Missing/extra/duplicate/stale/failed/incomplete rows, hosts,
profiles, domains, altered members and summary-only evidence fail closed.
Linux must also provide its successful parser build/passivity/638 comparison and
proof of the real twelve-row hosted root closure.

## Evidence boundary

Each host first verifies raw comparator outcomes at original same-host paths.
The compact capsule contains unchanged compressed raw observations, ordinary
lifecycle counterparts, rosters, input/build/plan/result bindings, small required
comparison artifacts, controlled failure logs, and a closed member inventory.
The compact archive is capped below32MiB. Final joining validates this transported
closure and actual raw row/count identities; it does not infer execution from a
summary or claim that hashes are cryptographic proof of execution.

Full source/stream/observer/binary evidence is separately archived. Cargo target
and cache directories are safely regenerable and are not evidence archives;
retained produced executables, recipes and raw observations are preserved.
Compact capsules disclose this replay boundary explicitly. Failure packaging runs
on `always()` and never changes a failed qualification status into a success.

## Verification and remaining branches

Bounded controls cover package omission/staleness/member change before execution,
missing/zero domain and profile, process exit propagation, missing/altered raw
observations, stale identities, duplicate/missing hosts and cross-host joins.
Commands, stdout/stderr, exit codes and actual outcome counts are retained.
No local synthetic control or historical receipt claims Windows/macOS/root-only
or fresh parser execution. Hosted exact-head CI is the final admission condition.

`gate.py local-only` uses the same compiler and corpus sequence, labels completion
`LOCAL_ONLY_PASS`, and cannot produce a qualifying hosted capsule. Its Linux
local-only route never invokes the root controller and cannot satisfy its
twelve-replacement branch. Hosted Linux checks its UID before any compiler build.
Only the local-only CLI accepts an explicit existing selected-runtime receipt;
hosted Linux always executes its dedicated pinned runtime stage.
