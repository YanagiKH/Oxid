# Stdlib feature integration packaging successor

This package derives exactly 19 canonical overlay targets for the composed
feature candidate. All 19 before bodies are archived and pinned;
existing historical aliases, inventories, generators and the v1 storage candidate
remain unchanged. `activation-manifest.json` records the combined review outputs.
Generation itself issues no publication or source/native qualification authority.

`successor.generate(repo, composition)` accepts only one of the four fixed
feature compositions (base, numbers, tables, combined). Its separate feature
descriptor pins exact owner patch hashes, file sizes, SHA-256, modes and Git blobs.
It rejects missing/extra feature members and modified descriptors or bodies.
The current 376-file source roster, 291 compiler bodies, source SHA and all
observer and scheduling budgets are unchanged.

The new dispatcher selects the unchanged v1 candidate. Parser, lifecycle and
hosted controls receive derived dispatcher bindings. The direct adapter routes
select the candidate and the new lifecycle/hosted helpers explicitly. A private
copy of the pinned old CI reader additionally routes the mechanical fixture's
`test_owned_array_native.py` read to its exact archived before body. The original
CI reader and its historical routes remain unchanged.

The new Unit4 physical inventory admits current feature files and all executable
package inputs and archives. Derived inventory/receipt/overlay copies are excluded
from recursive self-hashing; `verify_inventory` checks their exact regeneration,
the 54-file namespace, the receipt and every overlay body separately. The common
admission helper pins the complete per-composition inventory and feature verifier.
This is review-time generation, not publication or a new authority root.

The package's focused tests run in a composed checkout containing
its canonical overlay and per-composition inventory. From that checkout:

    python3 -B -m unittest discover -s tests/qualification/stdlib_feature_storage_activation_v3 -v
    python3 -O -B -m unittest discover -s tests/qualification/stdlib_feature_storage_activation_v3 -v

Optimized historical consumer refusal is required, not an optimized consumer pass.
Broader consumer logs and actual Rust feature test logs live in the external
recovery directory. The result ledger distinguishes final passes, failed attempts,
blocked dependencies and unrun native/full CI work. No capacity probe is included.

## Independent-review successor

Prior unpublished packages are preserved externally. This v3 pins all explicitly
named storage package members and every new static
producer input, authenticates the verifier before executing its captured bytes,
and independently checks each composition roster. Generation rejects unlisted
package members, verifies direct-adapter derivation and exact consumer routes,
and reuses captured verifier bytes for the generated runtime pin. The retained
reader bootstrap is also pinned; that was an inherited trust assumption.

The exact namespace and generated-metadata checks remain review-time guarantees
of verify_inventory; standalone common.admit authenticates its fixed executable
inventory and feature bodies, not the unused review overlay/receipt copies.
Scoped current-route execution traps are tested separately from deliberately
executed historical controls. No general alias or hostile-process hardening is
claimed. Missing upstream-v4/V2 raw inputs belong to the separate V3 lane and are
not inputs of this main-based increment.

## Packaging successor v3

Replaces the unpublished activation-v2 and fixture-v2 packages in the release
tree. The old storage test is exact non-discoverable data; its fixed derivation
ships one corrected suite. The four historical feature bodies and candidate/derive
semantics are unchanged. No published historical artifacts are edited.
