# Unit4 public replacement-v3 qualification

This additive implementation binds the independently approved public freeze
`12b40d321014719805f4864f297ba3598a3c4c5ec6f416de99a0218de68f2a85`.
It does not modify compiler sources, expectation assets, historical helpers,
historical constants, archived gates, or CI.

## Interfaces

- `contracts.py`: verifies the freeze, compressed and decoded contracts, external
  authority hashes, exact source maps, and full host/profile/operation/format tuples
- `compare.py`: literal streams, diagnostic projections, full origin validity,
  UTF-8 message limits, and exact logical lifecycle counters
- `runtime.py` / `process_tree.py`: bounded portable pipe capture, timeout/tree
  cleanup, manifest-bound executables, source preservation, tool observations,
  mode0000 capability proof, and copied-ELF execution with sources unavailable
- `predecessors.py`: unchanged Unit2/3 source and expectation identities, retained
  projection classifications/prose, and isolated Unit1 fixture regeneration
- `guards.py`: occupied-output preservation, post-link competitor injection and
  observer passivity/lifecycle checks
- `build.py`: isolated additive lifecycle source preparation and exact
  manifest-bound debug/release compiler build receipts
- `run.py`: inventory, collection, comparison, complete tuple gates and mutated
  negative controls. All output goes to an exclusive caller-selected directory

Run the deterministic controls without executing the compiler:

    python3 tests/qualification/unit4_public_v3/selftest.py

Inventory verifies source-only inputs without any candidate observations:

    python3 tests/qualification/unit4_public_v3/run.py inventory \
      --contracts /materialized/path/to/public-v3 --path-map /exact-path-map.json \
      --out /fresh/inventory

`--path-map` is an explicit JSON mapping of each original absolute logical input
path to its materialized transport path. Frozen files are never rewritten.
The current package's Unit1 compatibility manifest and its six files are verified
separately under the candidate repository at their original retained identities;
they are not claimed as members of the replacement-contract transport.

The run interface adds `--binding`, `--observer-binding`, `--llvm`, and `--libs`.
Default sections are `public,original,predecessors,lifecycle,guards`. `--pilot N`
runs only N local tuples per section and always reports `PILOT_ONLY`. It can never
satisfy the full contract. A source-free native receipt is mandatory for each
successful compile, including observer passivity compiles.

## Claim boundaries

A failed tuple or comparator failure makes its aggregate fail. Successful program
acceptance and successful qualification are separate: an expected rejection can
qualify. Every declared host has a tuple. Required other hosts are unavailable and
unqualified; excluded hosts have one explicit frozen-scope exclusion receipt.
Current successful execution qualifies only the current host. It cannot create a
global pass. An unavailable permission capability is an explicit unqualified gap.

Original streams retain all124 complete envelopes in both profiles. Predecessors
retain3603 Unit2 plus152 Unit3 cases; partial first-diagnostic, frontend-prefix and
schema/source projections remain partial. No public result claims private raw,
event, fuel or archived predecessor qualification. Lifecycle counters are logical
stage entries/completions, never OS syscall counts. Direct source coordinates are
validated even when a contract deliberately limits semantic diagnostic comparison.

Compiler binding records distinguish the actual Git head/full tree from the
source-only patch tree; the exact current-source manifest and profile build
receipts are the executable authority. Correcting a provenance label does not
change existing build receipts or binaries.

The Windows process capture implementation uses a suspended child placed in a
kill-on-close Job Object before resumption. Linux/macOS use owned process groups.
Only actual executed host controls support host-specific runtime qualification.

## Reviewed admission and portable denial collection

`authority.py` pins the exact237-input enum compiler manifest, the reviewed238-input
lifecycle overlay map and the current additive patch successor. Four exact
enum-era substitutions preserve the logical collection, parser and owned-route
hooks in the current execution bodies. The successor is `observer-enum-v1.patch`.
Reversing it restores the retained `observer-combined-v1.patch` exactly; reversing

historical additive patch. A caller cannot select a
different compiler body merely by supplying a coherent rewritten manifest.
`authority_controls.py` deterministically rejects both current-source and
observer-body forgeries without invoking a compiler.

The actual-host plan selects real LLVM only if a required local success/race
operation needs it. Every denial-only operation remains in the roster. A
no-native plan builds the small retained Rust trap and proves each configured
tool path records invocation and exits121. This needs Rust, but no LLVM tools or
runtime. Failure to build/execute a trap is a setup failure and cannot pass.

Native plans require `--runtime-receipt` in addition to `--libs`; they verify the
reviewed selected runtime content digest, exact SONAME/file/symlink membership,
and byte identities before/after. Ordinary host loader and system dependencies
remain outside that selected override-library identity claim.

All scripts suppress Python bytecode before local imports. Exact adapter package
membership includes every retained file and rejects extra files/directories;
there are no cache exclusions. Process reader errors propagate and cleanup is
bounded. POSIX normal-success cleanup kills descendants only for owned groups;
a nested real tool does not kill its enclosing candidate on successful return.

Unavailable mode-denial capability produces `INCOMPLETE_LOCAL_CAPABILITY`, a
full-run top-level `INCOMPLETE`, and exit2. It never makes the local full gate
green. Already executed passing rows remain individually available as evidence.

A section with no applicable local tuples is `NOT_APPLICABLE_THIS_HOST` only
after its entire frozen host/profile/operation roster is checked. Every receipt
must be a legitimate excluded/unavailable tuple; fabricated execution is rejected.
If even one local tuple is required, zero execution still fails. The selected-
local completion field is explicitly scoped to requested sections.

Windows compiler build receipts retain Cargo's `.exe` source/destination suffix.
The unchanged Unit1 generator may use Windows CRLF when writing its JSON intent
manifest. Raw generated bytes are retained; a narrowly scoped CRLF-to-LF projection
of that one manifest must exactly match the frozen original. Source files and
compiler streams are never normalized. Simulated CRLF, wrong-platform, lone-CR
and altered-content controls exercise this transport boundary.
